# Python: границы поиска и перебор разбиений

[Раздел Python](README.md) · [Задача 003](../problems/p003_render_batches/README.md)

## sum и max

```python
left = max(durations)
right = sum(durations)
```

`max` находит самое длинное задание, `sum` складывает все длительности. Каждая функция проходит по последовательности, поэтому обе вместе требуют `O(n)`, а не `O(1)`. Вычисляем их один раз до бинарного поиска.

Список и кортеж можно проходить повторно. Одноразовый итератор — другое дело: `max(iterator)` исчерпает его, и следующий `sum(iterator)` не увидит прежних элементов. Поэтому вычислительная функция принимает `Sequence[int]`, а ввод сохраняется в список.

## Целая середина

```python
middle = (left + right) // 2
```

`//` возвращает целую часть деления вниз. Здесь числа неотрицательны, и это обычное округление середины в меньшую сторону. `/` возвращает вещественное число, что не соответствует поиску целочисленного ответа.

Python `int` поддерживает целые произвольной точности: сумма `200000 * 10**9` не переполнит 32-битный тип. Но это не означает постоянную стоимость арифметики для сколь угодно длинных чисел; в рамках ограничений задачи стандартная оценка считает операции над ними константными.

## Возврат bool и раннее завершение

`can_finish` возвращает `True` или `False`. Выражение `if can_finish(...):` использует результат непосредственно. `return False` завершает **всю функцию**, а `break` завершил бы только ближайший цикл. Если заменить одно другим, оставшийся после цикла `return True` может дать ошибочный ответ.

## Префиксные суммы через accumulate

Эталон полного перебора часто считает суммы блоков. Подготовим префиксные суммы:

```python
from itertools import accumulate
prefix = list(accumulate([7, 2, 5], initial=0))
# [0, 7, 9, 14]
```

`prefix[i]` — сумма первых `i` элементов. Сумма блока с индексами `[start, end)` равна `prefix[end] - prefix[start]`. Подготовка требует `O(n)` времени и памяти, один запрос суммы — `O(1)`.

Полуоткрытый отрезок `[start, end)` включает `start` и не включает `end`; его длина `end-start`. Эти индексы относятся к срезам Python, а не к нумерации задания с единицы. Основному решению префиксные суммы не нужны: проверка всё равно идёт по всем заданиям последовательно.

## combinations: выбрать границы

Между `n` заданиями есть `n-1` мест для разреза. Чтобы получить ровно `k` непустых блоков, нужно выбрать `k-1` различных границ:

```python
from itertools import combinations
for cuts in combinations(range(1, count), workers - 1):
    ...
```

Например, для пяти заданий и двух блоков границы — `(1,)`, `(2,)`, `(3,)`, `(4,)`. Число вариантов равно биномиальному коэффициенту `C(n-1, k-1)`.

`combinations` выдаёт кортежи постепенно, не хранит весь набор вариантов. Однако ленивость не уменьшает количество перебираемых вариантов: в середине диапазона оно всё равно экспоненциально по `n`.

## Распаковка и pairwise

```python
boundaries = (0, *cuts, count)
```

Звёздочка распаковывает элементы `cuts` внутрь нового кортежа. Если `cuts=(2,4)` и `count=5`, получится `(0,2,4,5)`.

```python
from itertools import pairwise
for start, end in pairwise(boundaries):
    block_sum = prefix[end] - prefix[start]
```

Получаем пары `(0,2)`, `(2,4)`, `(4,5)`. Это соседние границы блоков. `pairwise` доступен с Python 3.10 и возвращает итератор.

## Генератор внутри max

```python
largest = max(prefix[end] - prefix[start] for start, end in pairwise(boundaries))
```

Генератор последовательно вычисляет суммы, а `max` оставляет наибольшую. Промежуточный список всех сумм не создаётся. Это экономит память на один вариант, но не отменяет перебор вариантов. В данном месте непустота гарантирована: всегда есть хотя бы один блок.

Официальная документация: [sum и max](https://docs.python.org/3.10/library/functions.html), [accumulate, combinations и pairwise](https://docs.python.org/3.10/library/itertools.html), [целочисленные типы](https://docs.python.org/3.10/library/stdtypes.html#numeric-types-int-float-complex).
