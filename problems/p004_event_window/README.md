# 004. Фрагмент журнала событий

[Задачи](../README.md) · [Разбор](editorial.md) · [Решение](solution.py) · [Эталон](baseline_bruteforce.py)

**Темы:** два указателя, скользящее окно, частотный словарь, амортизированный анализ.  
**Уровень:** базовый → средний.  
**Предварительно:** списки, циклы, функции; графы не требуются.

## Условие

Аналитик изучает журнал из `n` событий. Каждое событие имеет целочисленный идентификатор типа. Для подробного анализа нужно выбрать один непрерывный фрагмент журнала, содержащий не более `k` различных типов событий.

Найдите максимально длинный такой фрагмент. Если подходящих фрагментов несколько, выберите тот, который начинается раньше. События нельзя переставлять или пропускать внутри выбранного фрагмента. Ограничено число **различных типов**, а не общее количество событий каждого типа.

При `k=0` непустой фрагмент невозможен: выведите специальный пустой ответ.

## Ввод

Первая строка — `n k`. Вторая — `n` идентификаторов `a[i]`.

- `1 <= n <= 200000`;
- `0 <= k <= n`;
- `1 <= a[i] <= 10^9`.

Постановка учебная, без фиксированного лимита конкретного онлайн-судьи.

## Вывод

Первая строка — длина выбранного фрагмента. Вторая — его первая и последняя позиции, **с единицы, обе включительно**. Для пустого ответа выведите длину 0 и границы `0 0`.

## Пример 1

```text
8 2
1 2 1 3 3 2 2 2
```

Ответ:

```text
5
4 8
```

Фрагмент `[3,3,2,2,2]` содержит два типа и пять событий. Более длинного допустимого фрагмента нет.

## Пример 2: выбор при равенстве

```text
5 1
7 7 8 8 9
```

Ответ:

```text
2
1 2
```

Фрагменты `[7,7]` и `[8,8]` равны по длине, но первый начинается раньше.

## Пример 3: пустой ответ

```text
3 0
4 4 4
```

Ответ:

```text
0
0 0
```

## Упражнения

1. При равенстве длин возвращайте самый поздний фрагмент.
2. Найдите самый длинный фрагмент без повторяющихся типов.
3. Посчитайте количество непустых фрагментов с не более `k` типами.
4. Используя предыдущую функцию, посчитайте фрагменты с ровно `k` типами.
5. Почему замена ограничения «не более» на «ровно» требует дополнительной проверки ответа?
6. Можно ли тем же сжатием окна искать максимальный фрагмент с суммой не больше `S`, если элементы отрицательные?
