# Разбор задачи 006

[Условие](README.md) · [Решение](solution.py) · [Линейный эталон](baseline_bruteforce.py)

## От перебора к подготовке

Эталон перебирает все тарифы для каждой поездки. Он отбирает дальности не меньше длины поездки и берёт минимум цен. Суммарное время составляет `O(nq)`.

По сортировке дальностей все подходящие тарифы лежат от первой подходящей позиции до конца. Но цена на первой подходящей позиции может оказаться выше цены дальше по каталогу. Для этого и нужен заранее вычисленный минимум каждого суффикса.

## Как работает решение

1. Разделяем пары на дальности и цены.
2. Обходим цены справа налево и заменяем каждую минимумом её суффикса.
3. Для поездки длины `x` ищем `start = bisect_left(limits, x)`.
4. Возвращаем `best[start]`, если позиция внутри каталога. Для позиции после каталога возвращаем `-1`.

В первом примере `best = [100,100,100,130,130]`. Для длины 6 поиск возвращает индекс 3 с дальностью 8. Цена в `best[3]` равна 130 и соответствует тарифу на 10.

## Почему ответ верен

Индукция справа налево даёт точный минимум для каждого суффикса. Бинарный поиск находит начало суффикса подходящих дальностей. Все элементы до него имеют дальность меньше длины поездки. Все элементы начиная с него подходят, включая совпадающие пороги. Следовательно, суффиксный минимум даёт минимальную цену среди ровно тех тарифов, которые удовлетворяют условию.

Подготовка занимает `O(n)`, запрос — `O(log(n+1))`. Полное время с чтением и выводом составляет `O(n+q log(n+1))`. Структуры поиска требуют `O(n)` памяти, список ответов и обёртка ввода добавляют `O(q)`.

## Ошибки и проверки

| Ошибка | Последствие |
|---|---|
| Использовать `bisect_right` в основном решении | Пропускаются тарифы, подходящие на равенстве |
| Брать цену прямо в найденной позиции | Более выгодный тариф дальше в каталоге теряется |
| Читать позицию `len(limits)` | Поездка вне каталога вызывает ошибку индекса |
| Сортировать дальности отдельно от цен | Теряется соответствие между параметрами тарифа |

[Тесты](../../tests/test_trip_tariff.py) проверяют примеры и CLI, дубликаты и произвольные цены, полный перебор малых каталогов, 1000 случайных сравнений с эталоном и пакет из 200 000 поездок.

## Подсказки

1. Пары границ для 2, 5 и 11 равны `(0,0)`, `(1,3)`, `(5,5)`.
2. Для строгого условия используйте `bisect_right`.
3. Для `[a,b]` при `a<=b` ответ равен `bisect_right(limits,b) - bisect_left(limits,a)`.
4. Храните пары `(цена, индекс)`. Минимум кортежей сначала сравнивает цены, затем индексы.
5. Отсортируйте пары целиком по дальности. Если требуется исходный индекс, сохраните его до сортировки.
