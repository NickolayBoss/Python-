# Разбор: анаграммы в каталоге

[Условие](README.md) · [Решение](solution.py) · [Эталон](baseline_sorting.py)

## От перестановок к ключу

Перебирать перестановки не нужно: их число может достигать факториала длины. Сортировка символов сразу даёт каноническую форму: `кот` и `ток` превращаются в одну отсортированную строку. Этот подход реализован в эталоне.

Основное решение считает частоты через `Counter`, сортирует пары «символ, количество» и превращает их в кортеж. Например, ключи `abb` и `bab` равны `(('a', 1), ('b', 2))`. Для пустой строки ключ — `()`.

Сортировка пар обязательна: порядок первого появления символов у анаграмм может различаться. `tuple(Counter(name).items())` без сортировки не подходит. Сам `Counter` изменяемый и не может служить ключом словаря.

Для каждой строки добавляем её индекс в список по ключу. Новый ключ создаёт новую группу. Словарь сохраняет порядок добавления ключей, поэтому возвращение `list(groups.values())` даёт нужный порядок групп. Индексы добавляются по возрастанию.

## Пошаговый пример

| Индекс | Строка | Ключ | Группы после обработки |
|---|---|---|---|
| 1 | `ab` | `(('a', 1), ('b', 1))` | `[1]` |
| 2 | `aa` | `(('a', 2),)` | `[1]`, `[2]` |
| 3 | `ba` | `(('a', 1), ('b', 1))` | `[1, 3]`, `[2]` |
| 4 | пустая | `()` | `[1, 3]`, `[2]`, `[4]` |

## Корректность

Перестановка сохраняет число каждого символа. Значит, анаграммы имеют одинаковые частотные словари, а после сортировки — одинаковые ключи.

Обратно, равенство ключей означает равенство количества каждого символа. Можно сопоставить все вхождения каждого символа в двух строках, а затем переставить их на нужные места. Следовательно, строки являются анаграммами. Ключи равны тогда и только тогда, когда записи должны оказаться в одной группе.

Инвариант: после обработки первых `i` записей каждая из них находится ровно в одной группе своего ключа; группы расположены по первому индексу, индексы внутри возрастают. При добавлении записи существующий список только дополняется; новый ключ добавляется в конец словаря. Это сохраняет инвариант. После последней записи получаем требуемый ответ.

## Сложность

Пусть `m_i` — длина строки, `k_i` — число её различных символов, `L = Σ m_i`, `n` — число записей. Подсчёт частот занимает `O(m_i)`, сортировка пар — `O(k_i log(k_i + 1))`. Построение и хеширование кортежа занимает `O(k_i)`. При обычной средней оценке операций словаря итоговое время — `O(n + L + Σ k_i log(k_i + 1))`. Это не обещание константного времени для ключа любой длины.

Память — `O(n + L)` с учётом ключей, индексов и текущей строки. Строки читаются по одной. Для пустых названий работа всё равно зависит от `n`.

Эталон сортирует все символы: `O(n + L + Σ m_i log(m_i + 1))` времени и `O(n + L)` памяти. Когда все символы различны, частотный ключ не улучшает асимптотику сортировки. При длинных строках с повторениями сортируется меньше элементов.

## Ошибки и контрпримеры

- `set(name)` теряет количества: `ab` и `aab` ошибочно объединяются.
- Сумма кодов символов не задаёт состав: `ad` и `bc` имеют равную сумму.
- `.strip()` удаляет значимые пробелы: строки `ab` и ` ab` различаются.
- Нормализация регистра меняет условие: `A` и `a` должны остаться раздельными.
- Сортировка групп по ключам меняет требуемый порядок первого появления.

## Проверка

Тесты сравнивают частотное решение с независимым ключом из отсортированной строки: все каталоги длины 0–4 над семью короткими строками и 1000 случайных каталогов с фиксированным seed. Проверяются повторения, порядок, Unicode, значимые пробелы, примеры CLI, LF/CRLF, отсутствие последнего LF и границы `n`, `L`.
