# 002. Робот на поле указателей

[Каталог задач](../README.md) · [Разбор](editorial.md) · [Решение: 0–1 BFS](solution.py) · [Эталон стоимости: Дейкстра](baseline_dijkstra.py)

**Темы:** ориентированный взвешенный граф, кратчайший путь, релаксация, 0–1 BFS, восстановление маршрута.  
**Уровень:** средний.  
**Перед началом:** [BFS](../../algorithms/01_bfs.md), координаты клеток и очередь из первой главы.

В первой задаче мы выясняли, какие клетки связаны. Теперь требуется выбрать лучший маршрут, причём «лучший» определяется стоимостью, а не числом шагов.

## Условие

Робот перемещается по прямоугольному полю из `n` строк и `m` столбцов. Каждая проходимая клетка содержит указатель одного из четырёх направлений. Некоторые клетки заняты стенами.

| Символ | Значение |
|---|---|
| `U` | Стрелка вверх |
| `D` | Стрелка вниз |
| `L` | Стрелка влево |
| `R` | Стрелка вправо |
| `#` | Непроходимая стена |

За один шаг робот переходит в соседнюю по стороне проходимую клетку. Выходить за границы и проходить сквозь стены нельзя.

- Если направление шага совпадает со стрелкой **в клетке, из которой робот выходит**, шаг стоит 0 команд ручного управления.
- Если направление отличается, шаг стоит 1 команду.

Команда действует только на текущий шаг: стрелки поля не изменяются. Стрелка, направленная за границу или в стену, не разрешает такой переход; робот может выбрать другое допустимое направление за одну команду.

Известны стартовая и целевая клетки. Найдите минимальное суммарное число команд и выведите один маршрут с этой стоимостью. Минимизировать количество шагов среди маршрутов одинаковой стоимости **не требуется**.

Если цель недостижима, сообщите об этом. Старт и цель могут совпадать: в таком случае стоимость равна 0, а маршрут состоит из одной клетки. Стрелка цели не используется после завершения пути.

## Входные данные

Первая строка содержит `n m`. Следующие `n` строк содержат по `m` символов из `UDLR#` без пробелов. Затем идут две строки:

- `sr sc` — строка и столбец старта;
- `tr tc` — строка и столбец цели.

Координаты во входных и выходных данных нумеруются **с единицы**.

Ограничения:

- `1 <= n, m`, `n*m <= 200000`;
- обе заданные клетки находятся внутри поля и проходимы.

Это учебная постановка без привязки к онлайн-судье. Фактические лимиты времени и памяти зависят от платформы; сама печать длинного маршрута требует времени, пропорционального его длине.

## Выходные данные

Если пути нет, выведите единственное число `-1`.

Иначе выведите:

1. Минимальную стоимость маршрута.
2. Число клеток `k` в маршруте, включая старт и цель.
3. Следующие `k` строк — координаты клеток маршрута в порядке движения.

Выведите простой маршрут без повторения клеток; для неотрицательных стоимостей такой оптимальный маршрут всегда существует. При нескольких правильных ответах допустим любой из них. Число шагов равно `k-1`.

## Пример 1. Более длинный путь дешевле

Ввод:

```text
2 3
RRD
ULL
1 1
2 1
```

Один правильный вывод:

```text
0
6
1 1
1 2
1 3
2 3
2 2
2 1
```

Цель расположена прямо под стартом, но прямой шаг вниз идёт против стрелки `R` и стоит 1. Маршрут из пяти шагов вокруг поля полностью следует указателям и стоит 0. Это контрпример к применению обычного BFS, минимизирующего количество шагов.

## Пример 2. Одна команда

Ввод:

```text
2 2
RR
UU
1 1
2 2
```

Один правильный вывод:

```text
1
3
1 1
1 2
2 2
```

Первый шаг вправо бесплатен. Следующий шаг вниз из `(1, 2)` не совпадает с указателем `R`, поэтому стоит одну команду.

## Пример 3. Стена

Ввод:

```text
1 3
R#L
1 1
1 3
```

Вывод:

```text
-1
```

Ручная команда позволяет выбрать направление, но не убрать стену.

## Упражнения

1. Уберите восстановление пути и возвращайте только стоимость. Как изменится память?
2. Вместо команд минимизируйте шаги. Какой алгоритм теперь подходит? Как изменится ответ первого примера?
3. Сделайте цену отклонения от указателя равной 7 во всех клетках. Нужно ли обязательно переходить на Дейкстру?
4. Теперь цена отклонения задана отдельно для каждой клетки и может быть любой от 0 до `10^9`. Выберите алгоритм и оцените сложность.
5. Найдите минимальную стоимость от старта до всех проходимых клеток. Что нужно изменить в остановке алгоритма?
6. Требуется минимизировать сначала стоимость, затем число шагов. Объясните, почему текущая реализация этого не гарантирует. Предложите подход.
