# Разбор: баланс за период

[Условие](README.md) · [Том I](../../volumes/volume_01/README.md) · [Код](solution.py) · [Эталон](baseline_bruteforce.py)

## От предыдущей задачи к новой

В задаче 004 частотный словарь описывал текущий фрагмент. Здесь он хранит историю сумм до границ. Я выбираю этот переход, чтобы показать: одинаковая структура данных может хранить разные математические объекты.

Окно с безвозвратным сдвигом левой границы не подходит для сумм со знаками. Вместо монотонности используем точное равенство `P[r]-P[l]=s`.

## Базовое решение

Для каждого старта накапливаем сумму при расширении вправо и сравниваем с целью. Так не нужно пересчитывать каждый срез, но остаётся `O(n²)` сложений. Дополнительная память — `O(1)` поверх входа. При отрицательных числах нельзя прекращать проход по превышению цели: последующие значения могут уменьшить сумму.

Независимый эталон в `baseline_bruteforce.py` реализует именно этот перебор и используется только на малых данных.

## Основное решение

| Состояние | Смысл |
|---|---|
| `prefix` | Сумма уже прочитанных операций |
| `frequencies` | Частоты сумм до предыдущих границ |
| `answer` | Число подходящих периодов по обработанным правым границам |

Функция `count_segments` стартует с `{0:1}`. Для очередного значения обновляет сумму, прибавляет частоту `prefix-target` и только затем сохраняет текущий префикс. `solve` занимается разбором корректного конкурсного ввода и формированием строки ответа.

## Доказательство и сложность

Каждый найденный предыдущий префикс — допустимая левая граница по уравнению разности сумм. Текущая граница ещё не записана, поэтому все найденные периоды непусты. Разные вхождения одной суммы означают разные границы и должны считаться отдельно. Обработав каждую правую границу, учитываем все периоды ровно по одному разу.

Полный инвариант приведён в [главе алгоритма](../../algorithms/09_prefix_frequency.md). Время — ожидаемое `O(n)` при стандартной модели хеширования, память — `O(n)` на частоты. Массив префиксов не нужен, но словарь может содержать `n+1` ключей. Чтение всех байтов и токенов обёрткой также линейно по размеру входа.

## Ошибки

| Ошибка | Контрпример |
|---|---|
| Не добавить пустой префикс | `[3]`, цель 3: потерян единственный ответ |
| Сохранить префикс до запроса | `[1]`, цель 0: ошибочно посчитан пустой период |
| Хранить set вместо частот | Нули: одинаковые суммы соответствуют многим границам |
| Искать `prefix+target` | Перепутан знак в уравнении |
| Остановить перебор при превышении | `[5,-2]`, цель 3: подходящий период пропущен |
| Использовать float для счётчика | Необоснованная потеря целочисленной точности |

## Проверка

В [тестах](../../tests/test_balance_segments.py) перебираются все 3280 массивов длины 0–7 над `-1,0,1`, каждый для целей от -3 до 3. Есть 1000 случайных случаев, сравнение с независимым перебором, свойства разворота и смены знаков, проверка одноразового итератора, примеры и CLI.

Два случая из 200 000 элементов проверяют повторяющиеся и все различные префиксы. На нулевом входе ответ превышает 32-битный диапазон. Набор содержит 14 тестовых методов; вложенные переборы выполняют больше отдельных сравнений.

## Подсказки к упражнениям

1. Сохраняйте индекс ранее встреченного префикса и при нахождении партнёра восстановите `[l,r)`.
2. Для каждого значения храните самый ранний индекс; он даёт наибольшую длину при данном правом конце.
3. Храните последний предыдущий индекс. Запрашивайте до обновления, чтобы избежать нулевой длины.
4. Сумма кратна `m`, если остатки двух префиксов по модулю `m` совпадают. Считайте частоты остатков, начиная с `{0:1}`. Предполагается `m>0`.
5. Сортировка меняет соседство и допустимые периоды: `[1,-1,2]` и `[1,2,-1]` имеют разное число периодов суммы 0.
6. Нет: требуется число границ с данной суммой, а не факт существования хотя бы одной.
