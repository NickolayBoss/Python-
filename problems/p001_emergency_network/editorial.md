# Разбор: от BFS к офлайн-DSU

[Условие](README.md) · [BFS](baseline_bfs.py) · [DSU](solution.py)

## 1. Модель задачи

Фиксируем порог `t`. Каждая клетка с `a >= t` становится вершиной. Между работающими соседями по стороне есть ребро. Требуется количество компонент связности и максимальное число вершин в компоненте.

Это та же модель связности, что у поиска островов, но много независимых порогов меняют требования к эффективности. Я оставляю BFS как понятную исходную точку и независимый эталон для проверки оптимизации.

## 2. Базовый алгоритм

Для каждого порога создаём новую матрицу посещённости. Перебираем клетки, пропускаем неработающие и уже посещённые. Из каждой оставшейся запускаем BFS, увеличивая число сетей. Каждое извлечение из очереди увеличивает текущий размер на один. После завершения очереди обновляем максимум.

В коде `baseline_bfs.py` эти действия собраны в `analyze_network_bfs`. Для одного порога алгоритм работает за `O(N)`, для всех — за `O(QN)`. Память посещённости и очереди — `O(N)`, хранение ответов добавляет `O(Q)`.

Если запрос только один, это хороший окончательный выбор. При сотнях тысяч порогов повторные обходы слишком дороги.

## 3. Наблюдение, которое меняет решение

При снижении порога датчики только включаются. Если обработать запросы по убыванию, состояние можно постепенно наращивать. Для нового датчика достаточно создать одиночную компоненту и соединить её с уже работающими соседями. Связность при таких объединениях поддерживает DSU.

Не нужно запускать BFS после каждого изменения: число компонент и максимум хранятся в структуре и обновляются локально.

## 4. Структура основного решения

| Часть кода | Назначение |
|---|---|
| `DisjointSetUnion.__init__` | Неактивные клетки и начальные агрегаты |
| `activate` | Создание компоненты из одного датчика |
| `find` | Поиск корня с делением пути пополам |
| `union` | Объединение по размеру и обновление агрегатов |
| `analyze_network` | Сортировка, активация, обработка соседей и ответы |
| `solve` | Разбор входных чисел и форматирование результата |
| Точка входа | Чтение stdin и печать stdout |

### Шаг 1. Подготовить клетки

Матрица разворачивается в `values`. Клетка `(r, c)` получает номер `r * cols + c`. Список `cells` содержит номера клеток, отсортированные по устойчивости по убыванию. Исходная матрица не изменяется.

### Шаг 2. Подготовить запросы

Сортируются индексы запросов. Исходные пороги остаются на месте, а индекс позволяет сохранить ответ на правильную позицию. Массив `answers` заполняется в произвольном порядке и выводится в исходном.

### Шаг 3. Поддерживать границу активации

`next_cell` указывает на первую неактивированную клетку в отсортированном списке. Для очередного порога цикл `while` включает все клетки со значением `>= threshold`. Он не возвращается к уже включённым клеткам, поэтому всего выполняется не более `N` активаций.

### Шаг 4. Соединить соседей

После активации восстанавливаются координаты через `divmod`. Проверяются четыре направления, границы и активность соседа. Для активного соседа вызывается `union`.

Проверять только верх и лево нельзя: включение идёт по устойчивости, а не по строкам. Например, в строке `[3, 9]` правая клетка включится раньше левой; при включении левой понадобится проверить правого соседа.

Каждое ребро фактически обрабатывается при включении более позднего из концов. Если устойчивости равны, один конец всё равно включается раньше другого. Проверка уже общей компоненты в `union` нужна из-за циклов, а не из-за необходимости повторно считать ребро.

### Шаг 5. Сохранить состояние

Когда все подходящие клетки включены, `components` и `largest` — ответ для текущего порога. Значения записываются в `answers[query]`. Равные пороги не вызывают новых активаций и получают одинаковый ответ.

## 5. Пошаговый пример

Поле состоит из строки `[9, 3, 8]`, запросы идут в порядке `[3, 10, 8]`.

| Обрабатываемый порог | Новые клетки | Изменение компонент | Ответ |
|---|---|---|---|
| 10 | Нет | Пустой граф | `0 0` |
| 8 | 9 и 8 | Две изолированные клетки | `2 1` |
| 3 | Средняя 3 | Сначала третья компонента, затем два объединения | `1 3` |

В массиве ответов результаты записаны по исходным индексам. Поэтому вывод: `1 3`, затем `0 0`, затем `2 1`.

Размер крупнейшей сети при снижении порога не уменьшается. Число сетей может увеличиваться при появлении изолированной клетки и уменьшаться при появлении моста.

## 6. Доказательство корректности

**Инвариант активации.** Перед ответом на запрос `t` активны ровно клетки с устойчивостью не меньше `t`.

Клетки упорядочены по убыванию. Цикл включает их до первого значения меньше `t`, поэтому все подходящие клетки включены, а неподходящие — нет. Ранее включённые клетки тоже подходят, поскольку пороги обрабатываются по убыванию.

**Инвариант связности.** После каждой активации множества DSU совпадают с компонентами графа активных клеток.

Изначально граф пуст, утверждение верно. Новая клетка сначала образует отдельную компоненту. Все новые рёбра инцидентны ей: остальные активные клетки уже существовали. Алгоритм проверяет всех её активных соседей и объединяет множества ровно по этим рёбрам. Посторонние компоненты не объединяются; все новые связи учитываются. Инвариант сохраняется.

**Корректность агрегатов.** Активация добавляет одну компоненту размера 1. Успешное объединение разных корней уменьшает число компонент на один и складывает их размеры. Объединение одинаковых корней ничего не меняет. `largest` обновляется после каждой операции, способной его увеличить; удаления отсутствуют. Поэтому оба агрегата точны.

Из двух инвариантов и корректности агрегатов следует, что каждый сохранённый ответ соответствует требуемому порогу. Запись по исходному индексу обеспечивает правильный порядок вывода.

## 7. Оценка сложности

Пусть `N = n*m`, `Q = q`.

- Разворачивание матрицы и инициализация: `O(N)`.
- Сортировка клеток: `O(N log N)`.
- Сортировка запросов: `O(Q log Q)`.
- Каждая клетка включается один раз, проверяет максимум четырёх соседей: `O(N α(N))` суммарно на DSU.
- Сохранение и вывод ответов: `O(Q)`.

Итого: **`O(N log N + Q log Q + N α(N) + Q)` времени**, обычно сокращаемое до **`O(N log N + Q log Q)`** с учётом линейных членов. Память — **`O(N+Q)`**. При граничных значениях 1 логарифмические записи понимаются со стандартным линейным слагаемым.

В Python одновременно хранятся матрица, плоский список, порядок клеток, DSU, запросы и ответы. Асимптотика линейная, но фактические затраты больше, чем у компактных массивов языка C++. Ограничения этой учебной задачи не сопровождаются обещанием фиксированного лимита памяти онлайн-судьи.

## 8. Типичные ошибки

| Ошибка | Последствие | Правильный подход |
|---|---|---|
| `a > t` вместо `a >= t` | Пропадают клетки на границе | Сохранять нестрогое сравнение |
| Запросы по возрастанию | Потребуются удаления | Обрабатывать по убыванию |
| Ответ сразу после одной клетки группы | Неполное состояние для равного порога | Завершить весь `while` |
| Счётчик уменьшается за каждый контакт | Ошибка на циклах | Уменьшать только при разных корнях |
| Размер читается у произвольной клетки | Устаревший размер бывшего корня | Использовать размер представителя |
| Проверяются только верх и лево | Пропущенные связи | Проверять все четыре направления |
| Вывод в отсортированном порядке | Перепутаны сценарии | Сохранять исходные индексы |
| Диагонали считаются соседями | Объединены разные сети | Следовать четырём направлениям |

## 9. Проверки

Тесты лежат в [`tests/test_emergency_network.py`](../../tests/test_emergency_network.py). Для маленьких полей оптимизированное решение сравнивается с BFS, который независимо пересобирает граф для каждого порога. Это помогает ловить ошибки сортировки, счётчиков и равных значений.

Полный перебор рассматривает `3^6 = 729` сеток 2×3. Случайная проверка использует seed `20261109`, чтобы найденный случай можно было воспроизвести. Кроме того, проверяются примеры, отсутствие изменения аргументов, работа командной строки и однородное поле из 200 000 клеток. Эти проверки дополняют доказательство, но не заменяют его.

## 10. Подсказки к упражнениям

3. Строка `[9, 3, 8]` при порогах `9, 8, 3` даёт числа сетей `1, 2, 1`.
4. Добавьте четыре диагональных направления в оба алгоритма и измените ожидаемые ответы теста с диагональными датчиками.
5. При активации присваивайте сумму, равную значению клетки; при успешном объединении складывайте суммы корней. Для неотрицательных значений максимум поддерживается обновлением после активаций и объединений.
6. Изменение устойчивости может как добавить, так и удалить вершину из графа при фиксированном пороге. Порядок независимых порогов больше не описывает весь процесс; обычная DSU не умеет разделять компоненты.
