# Жадное разбиение при фиксированном лимите

[Алгоритмы](README.md) · [Бинарный поиск](06_binary_search_answer.md) · [Код проверки](../problems/p003_render_batches/solution.py)

## Проверяем один кандидат

Зафиксируем время `T`. Каждый сервер должен получить непрерывный блок с суммой не больше `T`. Сколько минимум блоков нужно?

Идём слева направо. Пока очередное задание помещается в текущий блок, добавляем его. Если не помещается — начинаем новый блок с этого задания. Если одно задание больше `T`, разбиение невозможно.

Жадный выбор: закончить каждый блок как можно позже, не нарушая лимит.

```python
used = 1
current = 0
for duration in durations:
    if duration > limit:
        return False
    if current + duration > limit:
        used += 1
        current = duration
        if used > workers:
            return False
    else:
        current += duration
return True
```

`used=1` корректно, поскольку вход непустой. При открытии блока нельзя терять текущее задание: его длительность сразу становится новой суммой `current`.

## Инвариант прохода

После обработки каждого задания обработанный префикс разделён на `used` допустимых блоков; `current` равен сумме последнего. Все завершённые блоки максимально продлены вправо: следующее задание уже не помещалось.

Этого достаточно, чтобы показать допустимость построенного разбиения. Для оптимальности количества блоков нужен ещё один аргумент.

## Почему жадный алгоритм использует минимум блоков

Сравним его с любым допустимым разбиением. Покажем по индукции: после `j` блоков жадный алгоритм обработал не меньше заданий, чем это разбиение.

Для первого блока всё очевидно: жадный алгоритм берёт самый длинный допустимый префикс.

Пусть после `j-1` блоков он уже прошёл не меньше заданий. Если он прошёл даже конец `j`-го блока сравниваемого решения, утверждение готово. Иначе оставшаяся до этого конца часть — суффикс `j`-го блока сравниваемого решения. Её сумма не больше `T`, потому что длительности положительны. Значит, жадный следующий блок способен дойти как минимум до того же конца.

Следовательно, если какое-либо решение покрывает очередь за `k` блоков, жадное покрывает её не более чем за `k`. Поэтому проверка количества блоков даёт точный ответ о допустимости.

## Ранний выход

Как только `used > workers`, можно вернуть `False`: мы уже построили префикс, которому нужно больше разрешённого числа блоков. Положительные будущие задания не уменьшат необходимые затраты на этот префикс.

При `current + duration == limit` новый блок не нужен: равенство допустимо. Поэтому используется строгое `>`, а не `>=`.

## Почему здесь важны неотрицательные значения

Для `[6, -2]` лимит 4 допускает один блок с суммой 4. Однако проверка `duration > limit` отвергнет первый элемент 6. Даже без неё жадные решения о границах по текущей сумме не учитывают будущую отрицательную компенсацию.

С нулевыми длительностями доказательство сохраняется: удаление префикса не увеличивает сумму оставшегося суффикса. В условии положительность выбрана для простоты модели времени, а не потому, что нули принципиально запрещены алгоритму.

## Оценка

Один проход — `O(n)` времени и `O(1)` дополнительной памяти. Никаких массивов блоков для проверки не нужно: достаточно их числа и последней суммы.

Этот жадный алгоритм не является универсальным решением любых задач распределения. Если разрешить перестановки или произвольные несмежные наборы, доказательство про префиксы больше не применяется.
