# DSU: система непересекающихся множеств

[Каталог алгоритмов](README.md) · [Реализация](../problems/p001_emergency_network/solution.py)

DSU (Disjoint Set Union, также Union-Find) хранит разбиение элементов на непересекающиеся множества. В задаче множество — работающая сеть, элемент — датчик.

## Устройство

Каждое множество представлено деревом ссылок на родителей. `parent[v]` — родитель элемента, а у корня `parent[root] == root`. Корень служит представителем множества. Его номер не имеет физического смысла: он не обязан быть первым датчиком, центром или клеткой с максимальной устойчивостью.

| Поле | Смысл |
|---|---|
| `parent[v] == -1` | Датчик пока не включён |
| `parent[v] == v` | Датчик — корень дерева |
| `size[root]` | Размер множества; значим у корня |
| `components` | Число текущих компонент |
| `largest` | Размер крупнейшей компоненты |

`activate(v)` создаёт отдельное множество из одного элемента. Оно увеличивает `components` и при необходимости обновляет `largest`. В текущей реализации активацию разрешено вызывать ровно один раз для каждой клетки; это обеспечивает указатель в алгоритме обработки.

## Поиск представителя

`find(v)` идёт по родителям до корня. Без оптимизаций цепочка может стать длинной. В коде используется **сжатие пути делением пополам**: на каждой итерации родитель текущей вершины заменяется её дедушкой.

```python
while parent[v] != v:
    parent[v] = parent[parent[v]]
    v = parent[v]
return v
```

Множество от этого не меняется: ссылка всё ещё ведёт к тому же корню. Но следующие поиски становятся короче. `find` вызывается только для активных элементов; иначе `-1` превратился бы в допустимый отрицательный индекс Python.

## Объединение по размеру

`union(a, b)` сначала находит корни. Если они равны, элементы уже принадлежат одной сети: ничего менять не нужно. Иначе корень меньшего множества подвешивается к корню большего. Размер нового корня увеличивается, число компонент уменьшается на один, максимум обновляется.

Почему это помогает? Когда дерево элемента оказывается меньшим и подвешивается к другому, размер его нового множества минимум удваивается. Без сжатия пути такой аргумент уже ограничивает глубину логарифмом числа элементов. Со сжатием пути последовательность операций имеет амортизированную стоимость `O(α(N))` на операцию, где `α` — обратная функция Аккермана, растущая крайне медленно. Это оценка всей последовательности, а не обещание одинакового времени каждого `find`.

## Пример

Три датчика имеют устойчивости `9, 3, 8` в одной строке. При пороге 8 включены крайние: два множества размера 1. При снижении порога до 3 включается середина: сначала становится три множества; затем два успешных `union` уменьшают счётчик до одного. Итоговый размер — 3.

Если новая клетка касается двух соседей, уже связанных обходным путём, первое объединение может быть успешным, а второе — нет. Уменьшать счётчик за каждое соседство нельзя: в графе могут быть циклы.

## Что DSU умеет и чего ей не хватает

DSU подходит для добавления связей, проверки принадлежности одной компоненте и хранения агрегатов по компонентам. Можно хранить сумму, минимум или максимум при условии корректного правила объединения.

Обычная DSU не поддерживает удаление ребра с возможным распадом компоненты и не хранит маршрут между вершинами. Для удаления или произвольных изменений нужны другие приёмы, например обратная обработка удалений или DSU с откатом в подходящей офлайн-модели. В первой задаче они не требуются.
