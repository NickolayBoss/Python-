# Бинарный поиск по ответу

[Алгоритмы](README.md) · [Монотонный предикат](../theory/03_monotone_predicates.md) · [Решение задачи 003](../problems/p003_render_batches/solution.py)

## Идея

Бинарный поиск работает не только по отсортированному массиву. Он может искать границу между ложными и истинными значениями функции на целочисленном диапазоне.

В третьей задаче проверка `can_finish(durations, workers, T)` отвечает, хватит ли времени `T`. Чем больше лимит, тем легче выполнить условие. Ищем минимально допустимый лимит.

## Шаблон первой истины

```python
left, right = lower_bound, feasible_upper_bound
while left < right:
    middle = (left + right) // 2
    if predicate(middle):
        right = middle
    else:
        left = middle + 1
return left
```

Это схема: `predicate` и границы определяются конкретной задачей. Здесь `right` — допустимая верхняя граница, а ответ изначально лежит в `[left, right]`.

При `left < right` середина строго меньше `right`. В истинной ветке правая граница уменьшается. В ложной ветке левая граница увеличивается минимум на один. Поэтому бесконечный цикл исключён.

## Трассировка

Для `[7, 2, 5, 10, 8]`, `k=2`:

| `left` | `right` | `middle` | Можно закончить? | Новый интервал |
|---|---|---|---|---|
| 10 | 32 | 21 | Да: `[7,2,5]`, `[10,8]` | `[10,21]` |
| 10 | 21 | 15 | Нет: нужны 3 блока | `[16,21]` |
| 16 | 21 | 18 | Да: нужны 2 блока | `[16,18]` |
| 16 | 18 | 17 | Нет: нужны 3 блока | `[18,18]` |

Ответ 18. На допустимой середине нельзя присвоить `right = middle - 1`: сама середина ещё может оказаться минимальным ответом.

## Доказательство

Изначально ответ находится в интервале по выбору границ. Если середина допустима, минимум не правее неё; если недопустима, монотонность исключает её и все значения левее. Поэтому каждая итерация сохраняет ответ внутри интервала. Интервал строго уменьшается и в итоге состоит из одного значения — минимального допустимого лимита.

## Сложность

Пусть `R = upper_bound - lower_bound + 1`, а одна проверка требует `C` времени. Число проверок — `O(log R)`, общее время с учётом подготовки — `O(подготовка + C log R)`. При `R=1` цикл не выполняется.

В задаче 003 одна проверка — `O(n)`, подготовка границ — `O(n)`, поэтому полная оценка **`O(n(1 + log R))`**. Её обычно записывают как `O(n log(sum(a)+1))`. Сам поиск и проверка требуют `O(1)` дополнительной памяти поверх сохранённого входа.

## Частые ошибки

- Делить через `/` и получать `float` вместо целой середины.
- Использовать `left = middle` в этом шаблоне: на двух соседних значениях возможен цикл.
- Искать до первой подходящей середины, не проверяя меньшие значения.
- Менять порядок входа, считая, что бинарному поиску обязательно нужен отсортированный список.
- Перепутать «можно при лимите T» и «минимальный ответ точно равен T».

## Связь с bisect

Модуль `bisect` ищет позицию вставки в отсортированной последовательности. Идея границы похожа, но в нашей задаче нет готового массива значений предиката; каждый его элемент пришлось бы вычислять за отдельный проход. Явный цикл делает эти затраты и инвариант понятными. Для вставки в обычный отсортированный список уместно изучать `bisect` отдельно.
