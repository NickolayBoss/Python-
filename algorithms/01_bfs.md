## Как работает очередь

BFS использует порядок FIFO: первым обрабатывается тот, кто раньше попал в очередь. Начальная вершина помещается в `deque`; из левого конца извлекается текущая вершина; её ещё не посещённые соседи добавляются справа.

Например, из клетки `(0, 0)` сначала обнаружены `(1, 0)` и `(0, 1)`. Очередь содержит их именно в таком порядке. После извлечения `(1, 0)` её новые соседи добавятся после `(0, 1)`. При обходе по расстояниям это даёт последовательные слои графа.

```python
from collections import deque

queue = deque([start])
visited.add(start)
while queue:
    vertex = queue.popleft()
    for neighbor in neighbors(vertex):
        if neighbor not in visited:
            visited.add(neighbor)
            queue.append(neighbor)
```

Это схема: `neighbors` и `start` определяются конкретной задачей. Для поля вместо множества удобно использовать матрицу `visited`.

## Почему отмечаем при добавлении

Если отмечать вершину только при извлечении, два уже обработанных соседа могут добавить её дважды. Тогда простой подсчёт извлечений завысит размер компоненты. Отметка перед `append` гарантирует, что каждая вершина стоит в очереди не более одного раза.

`deque.append` и `deque.popleft` выполняются примерно за `O(1)`. Удаление первого элемента обычного списка через `pop(0)` требует сдвигать остальные элементы и занимает `O(k)` для списка длины `k`. Поэтому список с `pop(0)` может испортить линейную сложность обхода.

## Как получить все компоненты

Один BFS находит компоненту стартовой вершины. Для всех компонент перебираем клетки поля. Если клетка работает и ещё не посещена, запускаем BFS, увеличиваем число компонент на один, считаем размер и обновляем максимум. Посещённость общая для всего фиксированного порога.

Вершины с устойчивостью ниже порога вообще не входят в текущий граф. Проверка границ обязательна перед обращением к матрице: отрицательный индекс Python обращается с конца списка, а не сообщает об ошибке выхода слева.

## Корректность

Каждая добавленная клетка работает и соединена со стартом: первая — сам старт; остальные обнаружены через работающего соседа. Обратно, если работающая клетка достижима из старта, то вдоль пути до неё BFS последовательно обнаружит все клетки, в том числе её. Поэтому обход находит ровно одну компоненту целиком.

Внешний перебор запускает следующий BFS только из непосещённой клетки. Уже найденные компоненты повторно не считаются, а любая ещё не найденная компонента содержит клетку, на которой перебор однажды запустит обход.

## Сложность и ограничения

Для графа BFS требует `O(V+E)` времени и `O(V)` дополнительной памяти. В прямоугольной сетке у каждой вершины максимум четыре соседа, поэтому `E=O(N)` и один полный анализ занимает `O(N)` времени. Для `Q` независимых порогов прямой повтор даёт `O(QN)`.

Для единственного порога BFS проще и асимптотически быстрее сортирующего DSU-решения. Оптимизация становится полезной из-за множества запросов.

## Дальше

BFS находит кратчайшие пути по числу рёбер в невзвешенном графе, если хранить расстояния. Для произвольных неотрицательных весов это свойство не переносится: обычно нужен алгоритм Дейкстры. В текущей задаче расстояния вообще не требуются — только связность.
