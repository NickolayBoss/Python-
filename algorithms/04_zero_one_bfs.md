# 0–1 BFS: кратчайшие пути с двумя весами

[Алгоритмы](README.md) · [Теория расстояний](../theory/02_shortest_paths.md) · [Рабочий код](../problems/p002_robot_route/solution.py)

## Идея

Если текущая минимальная стоимость равна `d`, ребро веса 0 предлагает стоимость `d`, а ребро веса 1 — стоимость `d+1`. Для поддержания порядка обработки достаточно двусторонней очереди:

- улучшение через вес 0 добавляем **в начало**;
- улучшение через вес 1 добавляем **в конец**.

Это частный случай принципа Дейкстры: сначала окончательно обрабатываем минимальную из ещё не обработанных меток. Но для весов 0 и 1 сортировку приоритетов заменяет порядок двух соседних слоёв расстояния.

## Схема реализации

Ниже фрагмент для уже заданного графа `graph`, где `graph[v]` содержит пары `(neighbor, weight)`. Это схема ядра, а полная программа находится по ссылке выше.

```python
from collections import deque
from math import inf

distance = [inf] * vertex_count
distance[source] = 0
queue = deque([(0, source)])

while queue:
    cost, vertex = queue.popleft()
    if cost != distance[vertex]:
        continue
    for neighbor, weight in graph[vertex]:
        candidate = cost + weight
        if candidate < distance[neighbor]:
            distance[neighbor] = candidate
            entry = (candidate, neighbor)
            if weight == 0:
                queue.appendleft(entry)
            else:
                queue.append(entry)
```

В задаче на сетке отдельный `graph` не создаётся: соседи вычисляются из координат.

## Зачем хранить стоимость в очереди

Одна вершина может попасть в очередь сначала с меткой 1, а потом с улучшенной меткой 0. Старая запись физически остаётся. Сравнение `cost != distance[vertex]` позволяет пропустить её без повторного перебора соседей.

Храним пару `(стоимость на момент добавления, вершина)`. Это снимок метки, а не автоматическая ссылка на текущее значение массива. Тот же приём используется в Дейкстре с кучей.

## Инвариант порядка

Перед извлечением записи стоимости `d` очередь упорядочена по сохранённым меткам: в ней могут находиться записи слоя `d` и следующего слоя `d+1`. Новые записи веса 0 имеют метку `d` и идут в начало; веса 1 — метку `d+1` и идут в конец. Пропуск устаревшей записи порядок не меняет.

Несколько записей одинаковой стоимости могут обрабатываться в любом порядке. Нулевая релаксация способна поставить новую вершину впереди других равных, и это корректно: первична стоимость, а не время обнаружения.

## Почему извлечённая актуальная метка окончательна

Пусть извлечена вершина `v` с минимальной актуальной меткой `d`, но существовал путь дешевле `d`. На таком пути выберем первую ещё не обработанную вершину `y`; её предшественник `x` уже обработан. При обработке `x` релаксация дала бы `y` метку не больше стоимости префикса этого пути. Веса неотрицательны, поэтому префикс тоже дешевле `d`. Тогда `y` должна была обрабатываться раньше `v` — противоречие.

Это обоснование позволяет остановиться при **извлечении актуальной** записи цели. Остановка при первом добавлении цели неверна: её метка ещё может улучшиться.

## Время и память

Вершина окончательно обрабатывается один раз; её исходящие рёбра перебираются один раз. Каждое успешное улучшение создаёт одну запись, поэтому даже с устаревшими записями всего `O(V+E)` операций очереди. Операции с её концами константны по длине очереди. Итого время **`O(V+E)`**.

Массивы расстояний и родителей занимают `O(V)`, очередь записей в этой реализации — не более `O(V+E)`. Для сетки у каждой вершины до четырёх исходящих рёбер, `E=O(V)`, поэтому суммарная дополнительная память **`O(V)`**. Не нужно скрывать хранение старых записей, когда оценивается память общего графа.

## Когда метод применять нельзя

Если веса равны 0 и 7, можно разделить все веса на 7, решить задачу как 0–1 и умножить ответ. Но при весах 2 и 7 такое прямое преобразование недопустимо: оно меняет соотношение стоимости путей разной длины.

Если есть произвольные неотрицательные веса, используйте [Дейкстру](05_dijkstra.md) или другой алгоритм с подходящими предпосылками. Если все веса равны 1, обычного BFS достаточно.
