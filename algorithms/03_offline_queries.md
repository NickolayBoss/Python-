# Офлайн-запросы: изменяем порядок, сохраняем ответы

[Каталог алгоритмов](README.md) · [Пример применения](../problems/p001_emergency_network/editorial.md)

**Онлайн-обработка** отвечает на запрос до получения следующих запросов. **Офлайн-обработка** располагает всеми запросами заранее и может переставлять их для вычисления ответов. Выдавать результаты всё равно нужно в порядке, указанном условием.

## Монотонность

В задаче о датчиках `a >= t`. При уменьшении `t` множество работающих клеток только расширяется. Значит, если отсортировать пороги по убыванию, ни один включённый датчик не потребуется выключать. Это именно тот тип изменений, который поддерживает DSU.

В исходном порядке `8, 3, 8` пришлось бы включать, а затем выключать клетки. После перестановки `8, 8, 3` достаточно включений. Одинаковые запросы используют одно и то же состояние.

## Два упорядоченных потока

1. Сортируем клетки по устойчивости по убыванию.
2. Сортируем **индексы** запросов по значениям порогов по убыванию.
3. Держим указатель на первую ещё не включённую клетку.
4. Перед ответом на порог `t` включаем клетки, пока их устойчивость не меньше `t`.
5. После каждого включения объединяем клетку со всеми уже включёнными соседями.
6. Записываем результат на исходную позицию запроса.

Указатель на клетки никогда не возвращается назад. Хотя цикл `while` вложен в цикл по запросам, суммарно его тело выполнится не более `N` раз. Это типичный случай, когда вложенность циклов сама по себе не означает `O(NQ)`.

## Равные значения

До ответа на порог нужно включить **все** клетки со значением `a == t`. Порядок внутри этой группы не важен: после всей группы все соответствующие рёбра будут обработаны. Нельзя отвечать после первой клетки группы.

## Границы применимости

Метод работает, потому что исходная матрица постоянна, запросы независимы и доступны заранее, а сортировка создаёт однонаправленное изменение. Если следующий запрос зависит от предыдущего ответа или устойчивости изменяются между запросами, это решение нельзя переносить автоматически.

Число компонент при включении клеток может и расти, и уменьшаться. Для корректности нужна монотонность множества активных вершин, а не монотонность любого вычисляемого показателя.
