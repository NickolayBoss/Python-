# Монотонный предикат: от лучшего ответа к проверке

[Теория](README.md) · [Задача 003](../problems/p003_render_batches/README.md)

## Заменяем вопрос

«Какое минимальное время возможно?» — задача оптимизации. Попробуем сначала ответить на более простой вопрос: «Можно ли закончить за время не больше `T`?»

Обозначим ответ `P(T)`. Функция, возвращающая истину или ложь, называется **предикатом**. Здесь `P(T)` истинно, если очередь можно разделить на не больше `k` блоков с суммой каждого не больше `T`.

Если допустим лимит `T`, то допустим любой больший: можно оставить прежнее разбиение. Значит, на целых лимитах значения имеют вид «ложь, ложь, …, истина, истина, …». Нужна первая истина.

Это и есть монотонность, позволяющая применить бинарный поиск. Последовательность длительностей при этом не обязана быть отсортированной.

## Три отдельных доказательства

У решения есть три логически разные части:

1. **Монотонность задачи.** Увеличение лимита не запрещает уже допустимое разбиение.
2. **Корректность проверки.** Конкретная функция `can_finish` действительно вычисляет допустимость, а не приблизительную оценку.
3. **Корректность поиска.** Обновления границ сохраняют нужный ответ и приводят к первой истине.

Ошибочная жадная проверка не становится правильной от применения бинарного поиска. Поэтому во второй части доказывается отдельное свойство разбиения на блоки.

## Из чего получить границы

Нижняя граница `max(a)`: неделимое самое длинное задание должно целиком поместиться в один блок. Верхняя граница `sum(a)`: всю очередь может обработать один сервер.

Обе границы выводятся из модели. Число вроде `10**18` иногда тоже достаточно велико, но не объясняет устройство задачи и расширяет диапазон проверок.

Ответ не всегда равен округлённой средней нагрузке. Например, для `[7, 2, 5, 10, 8]` средняя на двух серверах равна 16, но из-за непрерывных блоков минимальный максимум равен 18.

## Инвариант поиска

В реализации поддерживается утверждение: минимальный допустимый лимит лежит в закрытом интервале `[left, right]`, причём `right` допустим.

- Если середина допустима, минимум не больше неё: `right = middle`.
- Если середина недопустима, все меньшие лимиты тоже недопустимы: `left = middle + 1`.

Когда границы совпадают, единственный оставшийся кандидат — ответ. Данный шаблон не требует, чтобы `left` был недопустим: он может уже равняться ответу.

## Когда идею можно переносить

Подход полезен, если ответ упорядочен, проверка монотонна, границы известны, а одна проверка существенно проще прямого поиска оптимума. Примеры направлений: минимальная вместимость, минимальная скорость, максимальное допустимое расстояние.

Направление монотонности бывает обратным: «истина, …, ложь». Тогда ищут последнюю истину другим согласованным шаблоном. Нельзя смешивать границы и обновления из разных шаблонов.

## Что не следует из монотонности

Монотонность не даёт готового алгоритма проверки. Даже при абстрактном разбиении с отрицательными значениями увеличение лимита сохраняет допустимость. Однако наша конкретная жадная проверка и границы `max(a), sum(a)` уже могут быть неверны: отрицательное значение способно компенсировать большой элемент. Предпосылки нужно проверять для каждой части решения отдельно.
