# Кратчайший путь: расстояние, вес и релаксация

[Теория](README.md) · [Задача 002](../problems/p002_robot_route/README.md)

## От достижимости к оптимальности

Достижимость отвечает на вопрос, существует ли путь. Задача кратчайшего пути требует выбрать путь с минимальной суммой весов рёбер. Вес может означать длину, время, плату или число команд. Поэтому слово «кратчайший» не обязательно означает меньшее число переходов.

В задаче 002 граф **ориентированный**: переход из клетки `u` в клетку `v` и обратный переход могут стоить по-разному. Например, в строке `RR` движение вправо стоит 0, а влево — 1. Возможность ходить в обе стороны не делает взвешенный граф неориентированным.

Обозначим через `δ(v)` настоящую минимальную стоимость пути из старта в `v`. Для недостижимой вершины она бесконечна. Алгоритм постепенно вычисляет эти значения.

## Предварительные расстояния

Массив `distance` хранит лучшие **уже найденные** стоимости, а не обязательно окончательные ответы. В начале старт имеет стоимость 0, остальные вершины — бесконечность.

Если `distance[u]` известно и существует ребро `u → v` веса `w`, найден путь до `v` стоимостью `distance[u] + w`. Если он дешевле прежнего, обновляем:

```python
candidate = distance[u] + weight
if candidate < distance[v]:
    distance[v] = candidate
    parent[v] = u
```

Эта операция называется **релаксацией ребра**. Каждая конечная метка соответствует реально найденному пути, поэтому она не может быть меньше истинного минимума. Но она может быть больше него: позднее найдётся более выгодный путь.

Ключевое отличие от BFS для компонент: «клетка уже обнаружена» не означает «её расстояние окончательно». Поэтому отметка `visited` при первом добавлении в очередь без разрешения улучшений здесь неверна.

## Какую очередь выбрать

| Веса рёбер | Подход | Как выбирается следующая вершина |
|---|---|---|
| Все равны 1 | BFS | Обычная очередь FIFO |
| Только 0 и 1 | 0–1 BFS | Два конца `deque` |
| Любые неотрицательные | Дейкстра | Минимальная метка из кучи |
| Есть отрицательные | Например, Беллман–Форд | Повторные релаксации; отдельно проверяются отрицательные циклы |

Это ориентир для общих графов: дополнительные свойства, например ацикличность, могут дать другой алгоритм. Вторая задача имеет только веса 0 и 1, поэтому общая куча не обязательна.

## Почему нулевые циклы не мешают

Цикл может иметь суммарную стоимость 0. Однако проход по нему не улучшает стоимость возвращения в ту же клетку. Строгое сравнение `<` отбрасывает равные кандидаты, поэтому нулевой цикл не порождает бесконечные добавления в очередь.

Любой путь с повторением вершины содержит цикл. При неотрицательных весах удаление цикла не увеличивает стоимость. Значит, существует оптимальный простой путь длиной не больше `V-1` рёбер. Для весов 0 и 1 его стоимость тоже не больше `V-1`. Это позволяет в задаче 002 использовать `N+1` как конечный маркер бесконечности, где `N=n*m` включает и стены.

Такой маркер зависит от доказанной границы. Если веса произвольные, нельзя без обоснования переносить `N+1`: используйте, например, `math.inf`.

## Восстановление пути

При улучшении расстояния сохраняем `parent[v] = u`. После вычисления ответа идём от цели к её предшественнику, затем к предшественнику предшественника — пока не достигнем старта. Полученную последовательность разворачиваем.

В 0–1 BFS и Дейкстре вершины окончательно обрабатываются в порядке минимальных расстояний. Предшественник назначается при обработке уже окончательной вершины, а строгие улучшения исключают переприсваивание через равный нулевой путь. Поэтому цепочка предшественников восстанавливает путь без циклов.

Ссылку на предшественника сохраняем только при **улучшении** расстояния. Если менять её на каждом равном кандидате, в нулевых циклах можно получить циклическую цепочку родителей.

## Два критерия — другая задача

Стоимость и длина — разные величины. Если нужно минимизировать сначала команды, затем шаги, сравнивают пары `(команды, шаги)` лексикографически. При переходе прибавляют `(w, 1)`. Один из подходов — Дейкстра с такими парами в очереди. Обычный порядок направлений в текущем коде влияет лишь на выбор одного из оптимальных путей и не гарантирует минимального числа шагов.
