# Окно, частоты и монотонная граница

[Теория](README.md) · [Задача 004](../problems/p004_event_window/README.md)

## Непрерывный фрагмент как состояние

Фрагмент задаётся двумя границами. В реализации удобно использовать полуоткрытый интервал `[left, right)`: начало входит, конец не входит, длина равна `right-left`. Пустой интервал имеет совпадающие границы.

Перебирать все пары границ дорого: непустых фрагментов `n(n+1)/2`. Но соседние фрагменты сильно пересекаются. Вместо повторного подсчёта можно обновлять состояние при добавлении справа и удалении слева.

## Какие данные достаточно хранить

Для ограничения на число типов нужно знать частоту каждого типа в текущем окне. Множества недостаточно: при удалении одного события тип может всё ещё встречаться дальше.

Например, в `[1,2,1]` удаление первого события оставляет тип 1 в окне. Словарь `{1:2, 2:1}` после удаления становится `{1:1, 2:1}`. Ключ удаляется только при нулевой частоте. Тогда число ключей точно равно числу различных типов.

## Почему левая граница движется только вперёд

Добавление события не уменьшает число типов. Удаление слева не увеличивает его. Если фрагмент нарушил ограничение, более длинный фрагмент с тем же правым концом тоже не подходит. Можно последовательно удалить элементы слева до восстановления допустимости.

Когда правый конец сдвинется дальше, ранее отвергнутый старт не станет допустимым: расширение не убирает типы. Поэтому возвращаться левой границей назад не требуется.

## Инварианты

После сжатия окна для текущего правого конца:

1. Словарь содержит точные положительные частоты элементов окна.
2. Число типов не превосходит `k`.
3. Левая граница — самая ранняя допустимая для этого правого конца.

Третий пункт означает, что рассматривается самый длинный допустимый фрагмент, заканчивающийся здесь. Обновляя лучший результат на каждом правом конце, получаем глобальный оптимум.

## Суммарная сложность

Вложенный `while` не даёт автоматически квадратичную сложность. Правый указатель делает `n` шагов, левый суммарно — не более `n`. Ни один из них не возвращается назад. При ожидаемой константной стоимости словарных операций всё решение работает за ожидаемое `O(n)`.

Это амортизированный анализ: оцениваем всю последовательность сдвигов, а не один внешний шаг, на котором сжатие иногда бывает длинным.

## Границы применимости

Важно свойство допустимости, а не само наличие двух индексов. Для сумм с отрицательными элементами расширение способно уменьшить сумму. Например, префикс `[5]` превышает лимит 3, но `[5,-2]` уже подходит. Безвозвратно удалив 5, можно потерять лучший ответ. Доказательство для числа типов нельзя автоматически переносить на произвольные условия.
