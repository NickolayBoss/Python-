# Python: Алгоритмическое программирование

**Русскоязычное практическое пособие: от условия задачи до обоснованного и проверенного решения.**

Я собираю здесь задачи, которые помогают понять алгоритмическое мышление: построить модель, выбрать структуру данных, доказать корректность и оценить затраты времени и памяти. Каждый разбор связывает теорию с работающим кодом и показывает, почему выбранный подход подходит именно к этим ограничениям.

Материалы рассчитаны на читателя, знакомого с переменными, условиями и циклами Python. Более сложные конструкции разобраны отдельно. Все решения запускаются на **Python 3.10+**, используют только стандартную библиотеку и не требуют сторонних пакетов.

## Первая глава: связность на сетке

[**001. Аварийная сеть датчиков**](problems/p001_emergency_network/README.md)

На прямоугольном поле размещены датчики с разной устойчивостью к помехам. Для каждого уровня помех нужно найти число работающих сетей и размер крупнейшей. Соседние по стороне работающие датчики соединяются друг с другом.

Разбор начинается с BFS для одного состояния и приводит к обработке множества запросов через сортировку и DSU. В нём есть два независимых решения, пошаговый пример, доказательство корректности и проверка оптимизированного алгоритма на малых переборах.

## Вторая глава: маршрут с минимальной стоимостью

[**002. Робот на поле указателей**](problems/p002_robot_route/README.md)

Следование стрелке бесплатно, изменение направления стоит одну команду. Требуется найти минимальную стоимость и восстановить маршрут. Глава объясняет переход от достижимости к расстояниям, релаксацию и 0–1 BFS; решение Дейкстрой служит более общим эталоном стоимости.

Порядок изучения: [теория кратчайших путей](theory/02_shortest_paths.md) → [0–1 BFS](algorithms/04_zero_one_bfs.md) → [Дейкстра](algorithms/05_dijkstra.md) → [разбор задачи](problems/p002_robot_route/editorial.md) → [конструкции Python](python/02_paths_and_priority_queues.md).

## Третья глава: бинарный поиск по ответу

[**003. Очередь рендер-фермы**](problems/p003_render_batches/README.md)

Очередь заданий нужно разделить между серверами на непрерывные блоки и минимизировать максимальную нагрузку. Вместо прямого перебора разбиений я проверяю заданный лимит жадным проходом и нахожу первый допустимый лимит бинарным поиском.

Порядок изучения: [монотонный предикат](theory/03_monotone_predicates.md) → [жадная проверка](algorithms/07_greedy_partition.md) → [бинарный поиск](algorithms/06_binary_search_answer.md) → [разбор задачи](problems/p003_render_batches/editorial.md) → [Python и itertools](python/03_search_and_itertools.md).

## Четвёртая глава: скользящее окно

[**004. Фрагмент журнала событий**](problems/p004_event_window/README.md)

Найдём самый длинный непрерывный фрагмент с не более `k` типами событий. Изучим два указателя, частотный словарь и суммарную оценку вложенных циклов. При равенстве длин вернём самый ранний фрагмент.

[Теория](theory/04_window_invariants.md) → [алгоритм](algorithms/08_sliding_window.md) → [Python](python/04_frequency_dict.md) → [подробный разбор](problems/p004_event_window/editorial.md).

## Как читать

1. Прочитайте [основы моделирования и сложности](theory/01_foundations.md).
2. Решите базовую версию первой задачи для одного порога.
3. Разберите [BFS](algorithms/01_bfs.md) и сравните его со своим решением.
4. Перейдите к полной версии: почему повторный обход становится дорогим?
5. Изучите [DSU](algorithms/02_dsu.md), затем [офлайн-обработку](algorithms/03_offline_queries.md).
6. Прочитайте [разбор реализации](problems/p001_emergency_network/editorial.md), запустите тесты и выполните упражнения.

## Как проверяется код

Для первой главы тесты включают примеры, границы, повторяющиеся пороги, диагональные клетки, слияние сетей, полный перебор 729 сеток 2×3 со значениями 0–2 и 1000 случайных случаев с фиксированным seed. Ответ DSU сравнивается с независимым BFS. Отдельно проверяются запуск из командной строки и поле из 200 000 клеток.

Для второй главы проверяются все 625 полей 2×2 со всеми парами проходимых стартов и целей, 1000 случайных случаев и путь из 200 000 клеток. Стоимости сравниваются с Беллманом–Фордом и Дейкстрой; допустимость и стоимость возвращённого маршрута проверяются отдельно. Для третьей главы используются независимый перебор разрезов, все 1092 массива длины 1–6 со значениями 1–3, 1000 случайных случаев, проверки монотонности и очередь из 200 000 заданий.

Для четвёртой главы проверяются все 3280 последовательностей длины 0–7 над тремя значениями при лимитах 0–4, 1000 случайных случаев и большие входы из 200 000 событий.

В пятой главе проверяются все 3280 знаковых массивов длины 0–7 для семи целевых сумм, 1000 случайных случаев и большие входы.

Всего в шести главах — 75 тестовых методов с вложенными переборами.

GitHub Actions запускает весь набор на Python 3.10 и 3.12. Это проверка корректности; тест на большом поле не является гарантией прохождения произвольного лимита времени на конкурсной платформе.
